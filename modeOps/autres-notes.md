## 2. Point PCA CEE – Structure de synthèse

> Remarque : le contenu détaillé de la réunion est conservé dans le document source.  
> Ici, on propose une structure de synthèse pour exploiter ces notes dans un référentiel Markdown.

### 2.1. Contexte général

- **Réunion** : Point PCA CEE.
- **Date** : 27/11/2025.
- **Participants** : à compléter (équipes métier, SI, exploitation, etc.).
- **Objectif** :
  - Suivi du **PCA** (Plan de Continuité d’Activité) pour le périmètre CEE.
  - Partage d’informations sur les risques, les solutions et le planning.

### 2.3. Suivi des décisions

Créer un tableau Markdown pour suivre les décisions :

| ID décision | Sujet                         | Décision prise                                 | Responsable | Échéance   | Statut  |
|------------|-------------------------------|-----------------------------------------------|-------------|-----------|--------|
| DEC-001    | Ex. Scénario de perte site X  | Mettre en place une réplication renforcée...  | [Nom]       | JJ/MM/AAAA | Ouvert |
| DEC-002    | Ex. Tests PCA                 | Planifier un test de bascule au S2 2026       | [Nom]       | JJ/MM/AAAA | À faire |

Ce modèle permet de transformer les notes brutes en **plan d’actions** suivi. fileciteturn0file3

## 3. Modèle de prise de notes pour réunions similaires

### 3.1. En-tête de réunion

Exemple d’en-tête standard :

```text
Titre      : [Nom de la réunion]
Date       : JJ/MM/AAAA – HH:MM
Périmètre  : [Application / Domaine]
Participants : [Liste]
Animateur  : [Nom]
Compte rendu : [Nom]
```

---

### 3.2. Corps de réunion

Structurer les notes comme suit :

1. **Contexte**
2. **Points à l’ordre du jour**
3. **Discussions**
   - 3.1. Point 1
   - 3.2. Point 2
4. **Décisions**
5. **Risques / alertes**
6. **Actions à suivre**

---

### 3.3. Plan d’actions

Utiliser un tableau systématique :

```markdown
| ID   | Action                            | Responsable | Échéance   | Statut      | Commentaires        |
|------|-----------------------------------|-------------|-----------|-------------|---------------------|
| ACT1 | ...                               | ...         | JJ/MM/AAAA | À faire     |                     |
| ACT2 | ...                               | ...         | JJ/MM/AAAA | En cours    | Détails utiles...   |
```

Ce format est particulièrement adapté à un suivi dans VS Code + Git.
